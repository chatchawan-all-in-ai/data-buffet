# 04 · Mapping — สินค้า สาขา โซน และแถวที่จับไม่ได้

> **LLM context**: รหัสของแต่ละห้างไม่ตรงกันเลย (สินค้า HP กับ BT หน้าตาเหมือนกันแต่ตรงกัน 0 รหัส)
> บทนี้บอกว่าเชื่อมด้วยอะไร ไฟล์ mapping อยู่ไหน ห้ามใช้อะไร และจัดการแถวที่จับไม่ได้ยังไง
> · ตัวเลขวัด 2026-09-05 ถึง 2026-09-16 · ข้อ ❓ = กลไกในโค้ดยังไม่ได้ยืนยัน (ตรวจในบท 05)

## 1. หลักใหญ่

1. **map ไม่ได้ → SK = -1 ห้ามทิ้งแถว** ทุก dim มีแถว -1 ("ไม่ระบุสาขา/สินค้า") ยอดจึงยังครบ
2. **ต้องมีรายงานยอดที่ยังเป็น -1** เพื่อตามแก้ (query ในบท 06)
3. **ข้อมูลหลักอยู่ใน mds** (ทีม MDS ดูแล — Wisut) dim ของเราอ่านจาก mds
   → ถ้า mapping ผิด แก้ที่ mds ไม่ใช่แก้ในโค้ด (ยกเว้นทางแก้ชั่วคราวที่จดไว้ในข้อ 5)

## 6. ภาค / ผู้จัดการภาค / Director

- join ด้วย `store_code` + **วันขายอยู่ในช่วง `StartDate`–`EndDate`** → ได้ภาค ณ วันที่ขาย
- `DirectorSK` เก็บไว้ (ผู้ใช้สั่ง) แม้ตอนนี้ทุกสาขาอยู่ใต้คนเดียวกัน (SK = 6)
- ภาคปัจจุบันอยู่ที่ `dim_sales_branch_mdt.RegionSK` (คนละชุดกับใน fact — ดูบท 03 ข้อ 5)
- `dim_report` มีบรรทัดรายงานต่อห้าง (`RegionID = 'DH'` มีแล้ว) ไม่เจอกลุ่ม → "Other"

## 7. เช็กลิสต์เมื่อมีสาขา/สินค้า/ห้างใหม่
1. สาขาใหม่ → ให้ BI/MDS เติมใน mds (คอลัมน์ ห้าง/Store/Branch/Zone) — ห้ามแก้ใน SQL
2. สินค้าใหม่ → ตรวจว่าบาร์โค้ด 885 อยู่ใน `dim_product_master` ไหม ถ้าไม่ (หรือเป็น BT) เพิ่มใน mapping
3. ห้างใหม่ → เพิ่ม `store_code` ใน `dim_report`, region, สาขาใน mds และ**วันตัด**ใน curated (บท 05)
4. รันแล้วดูยอดที่เป็น -1 (บท 06) ต้องไม่เพิ่มขึ้น
